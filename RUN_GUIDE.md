# TumarSystem: запуск на Windows и все страницы

Этот гайд описывает текущую реализацию в папке `C:\Users\Элдос\Desktop\TumarSystem-main`.

## 1. Из каких частей состоит проект

| Часть | Папка | Для чего нужна | Адрес при запуске |
| --- | --- | --- | --- |
| Сайт / frontend | `frontend` | Публичные страницы, форма входа и интерфейс кабинета | `http://localhost:3000` |
| Сервер / backend | `backend` | Проверка пароля, выдача токена, данные пользователя | `http://localhost:8000` |
| База данных | PostgreSQL, сервис `db` в Docker | Хранит учётные записи | Не открывается как веб-страница |

Чтобы посмотреть дизайн и публичные страницы, достаточно frontend. Чтобы войти в личный кабинет, нужны все три части и созданный пользователь.

## 2. Быстро посмотреть сайт без Docker

Node.js на этом компьютере уже доступен: при проверке обнаружена версия `v24.21.0`. Python для этого способа не нужен.

1. Откройте PowerShell или терминал в VS Code.
2. Перейдите в папку frontend:

```powershell
cd "C:\Users\Элдос\Desktop\TumarSystem-main\frontend"
```

3. Установите зависимости, если запускаете проект впервые или они изменились:

```powershell
npm.cmd ci
```

Если команда сообщает, что `package.json` и `package-lock.json` не совпадают, выполните:

```powershell
npm.cmd install
```

4. Запустите сервер разработки:

```powershell
npm.cmd run dev
```

5. Дождитесь сообщения `Ready` и откройте в браузере:

```text
http://localhost:3000
```

Оставьте терминал открытым: он обслуживает сайт. Изменения файлов отображаются автоматически. Чтобы остановить сайт, нажмите `Ctrl+C` в этом терминале.

В PowerShell используйте `npm.cmd`, а не `npm`: это позволяет обойти блокировку файла `npm.ps1` политикой выполнения скриптов без изменения настроек Windows.

При запуске только frontend публичные страницы открываются, но вход не сможет проверить учётную запись, пока backend не запущен.

## 3. Запустить всё приложение через Docker

Это удобный способ запустить сайт, сервер и базу одной командой. Docker CLI установлен на этом компьютере; перед запуском откройте Docker Desktop и дождитесь готовности движка. Локальная установка Python для этого способа не нужна.

### Шаг 1. Откройте корень проекта

```powershell
cd "C:\Users\Элдос\Desktop\TumarSystem-main"
docker compose version
```

### Шаг 2. Проверьте конфигурацию

В корне проекта уже есть файл `.env`. Не заменяйте его шаблоном при обычном запуске.

Если вы перенесли проект на другой компьютер и `.env` отсутствует, создайте его:

```powershell
Copy-Item -LiteralPath ".env.example" -Destination ".env"
```

Откройте `.env` в редакторе. Замените `POSTGRES_PASSWORD` и `JWT_SECRET_KEY`, содержащие `CHANGE_ME`, на собственные случайные значения. JWT-секрет должен содержать минимум 32 символа. Остальные значения шаблона подходят для локального запуска.

Для генерации случайного значения можно выполнить команду ниже два раза и использовать разные результаты для пароля БД и JWT-секрета:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

### Шаг 3. Соберите и запустите сервисы

```powershell
docker compose up --build -d
```

При первом запуске Docker скачивает образы и устанавливает зависимости. Это может занять несколько минут.

Проверьте состояние:

```powershell
docker compose ps
```

Должны быть запущены `db`, `backend` и `frontend`. Для `db` и `backend` предусмотрена проверка здоровья. Frontend запускается после готовности backend.

Откройте сайт: `http://localhost:3000`.

### Шаг 4. Создайте пользователя для входа

Публичная регистрация пока не создаёт аккаунт. Пользователь создаётся командой в backend:

```powershell
docker compose exec backend python -m app.create_user --username admin --email admin@example.com
```

`admin@example.com` здесь является примером для локальной учётной записи. Можно заменить его своим email. Логин `admin` также можно заменить.

Команда попросит пароль и его повтор. Символы при вводе не показываются — это нормально. Пароль должен содержать минимум 8 символов. Готового стандартного пароля в проекте нет.

После сообщения «Пользователь создан» откройте `http://localhost:3000/login` и введите выбранный логин или email и установленный пароль. После успешного входа откроется `/dashboard`.

Повторять создание пользователя при каждом запуске не нужно: аккаунт сохраняется в базе данных.

### Ежедневный запуск, остановка и обновление

Запуск уже собранного проекта:

```powershell
docker compose up -d
```

Остановка:

```powershell
docker compose down
```

После изменений кода пересоберите контейнеры:

```powershell
docker compose up --build -d
```

Обычная команда `docker compose down` сохраняет данные PostgreSQL в томе. Не добавляйте флаг `-v`, если хотите сохранить пользователей.

Просмотр журналов:

```powershell
docker compose logs --tail 100 backend
docker compose logs --tail 100 frontend
docker compose logs --tail 100 db
```

Чтобы наблюдать новые сообщения непрерывно, используйте `docker compose logs -f`. Выход из просмотра — `Ctrl+C`.

## 5. Языки и интерактивные элементы

- RU / KY / EN в шапке и подвале переключают основные тексты публичных страниц. Выбор сохраняется в этом браузере.
- Форма входа также поддерживает RU / KY / EN.
- Текущий защищённый кабинет и его заготовки пока на русском языке.
- На мобильном экране навигация открывается кнопкой меню в шапке.
- Сценарии света меняют визуализацию на сайте; команды устройствам не отправляются.
- В блоке устройств переключаются варианты представления интерфейса.
- FAQ раскрывается нажатием на вопрос.

## 7. Backend без контейнера: для разработки

Этот способ нужен, если вы хотите редактировать Python-код и автоматически перезапускать сервер. При проверке команды `python` и `py` на этом компьютере не обнаружены в PATH. Для этого варианта сначала установите Python 3.12+ с добавлением в PATH и откройте новый терминал. Альтернатива — полный запуск через Docker из раздела 3.

Нужен работающий PostgreSQL. Чтобы запустить только БД из проекта и открыть её для локального backend, создайте в корне `compose.local.yml`:

```yaml
services:
  db:
    ports:
      - "127.0.0.1:5432:5432"
```

Затем из корня выполните:

```powershell
docker compose -f docker-compose.yml -f compose.local.yml up -d db
```

Корневой `.env` должен содержать данные этой БД, JWT-секрет и `DB_HOST=localhost`.

В отдельном терминале:

```powershell
cd "C:\Users\Элдос\Desktop\TumarSystem-main\backend"
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Виртуальную среду активировать не обязательно: команды выше вызывают её Python напрямую.

После запуска backend создайте пользователя в ещё одном терминале:

```powershell
cd "C:\Users\Элдос\Desktop\TumarSystem-main\backend"
.\.venv\Scripts\python.exe -m app.create_user --username admin --email admin@example.com
```

Frontend запускается отдельно командой `npm.cmd run dev`. По умолчанию он обращается к `http://127.0.0.1:8000`.

Если backend работает на другом адресе, создайте `frontend/.env.local` на основе `frontend/.env.example` и укажите `BACKEND_URL`. Перезапустите frontend после изменения переменных окружения.

## 8. Если что-то не запускается

| Проблема | Что сделать |
| --- | --- |
| `npm.ps1` заблокирован | Использовать `npm.cmd` во всех командах |
| Команда `npm.cmd` не найдена | Установить Node.js и открыть новый терминал |
| Docker не соединяется с движком | Открыть Docker Desktop, дождаться запуска и повторить `docker compose up --build -d` |
| Docker сообщает `Set POSTGRES... in .env` | Проверить наличие и заполнение `.env` в корне проекта |
| Порт 3000 занят | Остановить предыдущий frontend через `Ctrl+C`; для разработки можно запустить `npm.cmd run dev -- --port 3001` и открыть `http://localhost:3001` |
| Вход сообщает о недоступности сервера | Запустить backend и БД, проверить `http://localhost:8000/api/v1/health` |
| Неверный логин или пароль | Проверить данные созданного пользователя; стандартного пароля нет |
| «Логин, email или телефон уже используется» | Аккаунт уже существует; войти с ним или создать пользователя с другими данными |
| Пользователь не создаётся из-за отсутствия таблицы | Сначала запустить backend: при его старте создаётся таблица пользователей |
| `/account/...` открывает страницу входа | Это ожидаемое поведение без действующей сессии |
| Кнопка отправки заявки отключена | Канал приёма заявок пока не реализован; это текущее состояние сайта |
| Sitemap пустой | Для публичного развёртывания задать подтверждённый `NEXT_PUBLIC_SITE_URL` и пересобрать frontend |

При работе frontend на порту 3001 для полного локального приложения также добавьте `http://localhost:3001` в JSON-массив `CORS_ORIGINS` корневого `.env` и перезапустите backend.

## 9. Где редактировать сайт

| Файл / папка | Что редактируется |
